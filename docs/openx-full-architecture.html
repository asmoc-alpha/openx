读法：自上而下 -- 组合输入决定出厂形态；端只渲染与上送；协议是账本的外化；内核五件套装配一切、把关一切、记录一切，loop 与零件被装配而非自举；插件层纵贯四层，经候选池 -> 配对 -> 晋升门 -> 激活 -> 记账插入任何一层。自演进闭环纵贯全局 -- 它的每一步都只是"改组合输入 + 过门 + 记账"，因此内核零改动。
与 v4.1 总架构图的差异：本图是完全态 -- ①内核按五件套展开（推理/装配/审计/轨迹/沙箱，四职责同构映射）；②补入已落地的元工具面与自产插件（P-A~P-F）；③Web 端由"新增"改标"已落地"；④新增自演进闭环层（六环三主线）与 E 系列切片；⑤落地路线分已完成 / 下一步 / 自演进三档。
自演进走一遍：排障时发现缺日志解析能力 -> write_plugin 生成 auto-logparse（manifest + 代码 + self_test）-> AST 扫描 + daemon 线程自测跑绿 -> 会话热插立即可用 -> 用户确认晋升 persistent，plugin_promoted 上全局账本 -> 下次 boot 经 overlay 进应载清单 -> 后续任务经 list_plugins 摘要配对复用 -> 若熔断频发，轨迹显现，整体回滚 auto-* 一键撤出。
消融走一遍：模型升级 -> 能力档案更新 -> 历史压缩的 exit_when 命中 -> 在长会话 eval 集上对比"带压缩 vs 摘除"，成功率不掉点 -> 用户确认 -> scaffold_retired 决策记账 -> 从动态 base 摘除（代码仍在仓库）-> 日后模型降级，档案回退，自动回挂并记 scaffold_restored。

模块详注

⓪ 组合输入

模型能力档案 / 动态 baseP6
档案按模型版本声明能力面，与协议层的版本协商对称：一个面向端，一个面向模型。脚手架以 requires / exit_when 声明依赖，loader 据此计算应载清单。换模型、模型升级 -> 组合自动变化，零代码改动。决议记账 composition_resolved 使任何一次会话的组合都能事后复现。
演进产物回写自演进
自演进不改内核，只改组合输入：晋升的 auto-* 插件写回组合（E7）、轨迹学出的装配策略落成 overlay 补丁（E5）、退场评测通过的脚手架从组合摘除（E4）。三类回写同走补丁原语，同过决议记账。

① 端层

薄客户端原则不变量
端只做两件事：渲染事件流、上送意图流。路由、压缩、审批判断出现在任何一端都会导致多端行为分叉。渲染是纯函数：端不得持有会话状态语义。
CLI / WEB / DESKTOP / IDE·移动两端已落地
CLI 是参照实现，插件 deck 面板每帧征集（崩溃跳过/熔断）；Web 经 openx serve 提供会话长存、多端 attach、远程批准（fail-closed：断流/超时/未匹配 request_id 一律拒绝）、复盘回放与 panels 广播。Desktop / IDE / 移动是预留位。

② 会话协议层

协议 = 账本的外化不变量
事件信封（seq/ts/cause/origin/digest 哈希链）定义在 kernel/protocol.py，下行事件 = 信封去掉簿记字段的投影。回放 = 重发存储事件；动作永不重放。cause 链即归因链："这行代码是哪次批准的哪个工具改的"是一条链上溯。
openx serveP4 已落地
会话长存在 serve 进程，客户端 attach/detach，关终端 agent 继续跑（tmux 语义）。串行回合队列保持 REPL 语义；权限桥广播 permission_request / ask_user / plan_request，fail-closed 等待。

③ 微内核五件套

① 推理核心部分落地
provider 形状与重试/退避已入核（kernel/reasoning）。路由 / fallback / 限流随多 provider 成熟度入核（决断 N2）。入核理由：没有它模型不会思考，"由模型决定装配"不成立。
② 插件装配器已落地
注册目录表驱动（K1）：tools / commands / contexts / lifecycle / ui_slots / providers 逐类元数据，新增一类注册项 = 目录加一行 + 校验器，不改内核主体。五阶段 loader；动态插入复用同一五阶段（同源同门）。消费方装配策略（实例化仲裁 / provider 解析 / 命令分发）已迁出内核（K3a）。
③ 安全审计已落地
Guard 七站裁决管线（K3）：Verdict 半格上确界折叠，任何站只升严不降宽；hooks 按映射表折入第④站；高危强制与存储裁决固定序，存储永不放宽危险。每次裁决记 permission_decision（含逐站 trace）。资源闸析出为 K4；晋升门 admit 以 MCP 为 pilot（K6）。
④ 轨迹跟踪部分落地
append-only 是物理的：内核只有 emit()，账本只以追加模式打开。记账先于动作。会话账本已升格（K2），全局账本与决策事件族随 K5，成本字段与 eval 导出随 P-E -- 后者是自演进调优线的数据底座。
⑤ 沙箱执行器部分落地
ToolHost（K3a）：工具工厂 factory(host)，host 是 agent 的只读数据投影 -- 插件任何阶段拿不到 loop / 闸门 / llm / 完整 config。调用防护（P-C）：timeout / 输出上限 / 熔断（3 次失败自动摘除）/ 结构化错误。执行隔离（进程沙箱）为 D9 远期加固，auto 级不可降级。

④ LOOP 核心与零件层

loop 槽默认实现已落地
接口形状（意图进、事件出、工具调用必经执行闸、每轮必过资源闸）是内核不变量，实现进槽。默认 = harness loop；预留 model-native 位。装配 loop 的机制独立于 loop -- 这是"换 loop 不换产品"的前提，也是内核在 loop 之上的原因。
零件与槽全可换
Provider / Context / Executor / Tools 全可换。协调与记忆当前硬连线（orchestration/*、memory.py），P2+ 逐步插件化为协调槽与 memory_backends 注册项。压缩策略槽暂不开放；审计闸门槽倾向开放且只紧不松。

⑤ 插件层（纵贯）

候选池与模型配对已落地
Manifest 自描述（P-B）：type / trust / permissions / cost / summary，摘要进目录索引、schema 按需展开。模型决定"用哪个插件、建议注册什么"，但注册项类型由内核枚举（标准六）-- prompt injection 最坏结果是推荐错插件。三个来源同池：第三方 / 用户 / 模型自产（auto-* 独立信任档）。
协议分类四类已落地
类别 -> 协议 -> 装配层三级映射（P-D）：插件面向协议编程，不面向内核实现。tool/context/lifecycle/ui 四协议已落地（ui/v1 双端哑渲染，渲染路径强制故障隔离）；planner / orchestrator / ingress / event-listener 占位，单例协议"装配即替换"的仲裁待落。新增插件类别 = 新协议 + 新挂点 + 新注册表，内核五件套一行不动。
自产插件（Self-Extension）已落地 P-F
PluginSpec 是模型可读的协议自描述（常驻系统提示）；write/test/promote 三元工具；admit 管线 = 形状校验 -> AST 静态扫描 -> daemon 线程自测（10s 挂死即拒）-> 会话热插 -> 用户晋升 + plugin_promoted 记账。信任锚点是"沙箱里自测跑绿"，不是"模型说它能用"。

⑥⑦ 脚手架与自演进

脚手架退场将消融
退场三步：评测门（证据不是声明）-> 决策记账 -> 从动态 base 摘除。摘除不是删除：模型降级时自动回挂。harness loop 默认实现是最大的脚手架，也是消融收益最大的一块。
自演进闭环新增
六环：感知缺口 -> 生成候选 -> 沙箱验证 -> 晋升门 -> 灰度激活 -> 评测退场，轨迹全程回流。三主线：增生（自产插件沉淀能力库，目录索引供复用）、消融（脚手架有序退场）、调优（装配 / 上下文 / 记忆 / 权限规则从轨迹学出，overlay 过门生效）。每条变更三要素缺一不可：有证据、有审批、有痕迹。
治理与度量新增
审批矩阵：auto 级写类插件 = self_test + 用户确认 + session 灰度；overlay 建议永远用户终审；棘轮 / 评测门对一切动态插入关闭。健康度 KPI：任务成功率、自产插件存活率、配对命中率、回滚率、脚手架净重、权限摩擦、证据完备率（恒 100%）。
