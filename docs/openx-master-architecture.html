OpenX 总架构 -- 会消融的 harness

五层骨架：端（薄）-> 协议（账本外化）-> 内核（编排 / 沙箱执行 / 插件维护 / 记账）-> 循环与零件（全可换）-> 插件层（纵贯四层，模型配对 + 内核插入）

不变量机制层 · 任何贡献不可替换 / 松动
loader / ctx / 注册表自身 安全底线（含团队安全语义） 账本格式 + 协议核心 schema 槽接口形状（loop / 执行 / 协调） 资源闸（停止 / 预算 / 轮次底线） 贡献点枚举（模型只配对，内核才定位） TCB 对动态插入关闭
读法：自上而下--端只渲染与上送；协议是账本的外化，回放即重放；内核装配一切、把关一切、记录一切；loop 与零件被装配而非自举；插件层纵贯四层，经候选池 -> 配对 -> 晋升门 -> 激活 -> 记账插入任何一层。自下而上看演进--脚手架随模型进步经评测门退场，安全与账本随模型进步变重。
五层各答一问：端答"人在哪看"；协议答"事件怎么流"；内核答"什么永远不变"；loop 答"今天怎么干活"；插件层答"明天怎么长出新能力"。
与前版的差异：v1（目标架构）定义契约面与服务槽；v3（微内核拆解）定义 TCB 边界；本版把内核收缩为编排 / 沙箱执行 / 插件维护 / 记账四职责（loop / executor / 预算 / 协调四项不变量降级为槽与脚手架），新增模型能力档案与动态 base、脚手架退场机制、纵贯插件层（模型配对 + 内核插入 + 热插分级）。
可视化插件走一遍：用户说"画出调用关系" -> 模型从候选池配对 viz 插件（自描述：UI slot + 数据工具 + x-viz.* 事件）-> 内核校验 UI slot 只加面板不动主转录区 -> 用户确认一次 -> 激活并经协议下发 ui_slot_registered -> CLI / Web / Desktop 同时多出图表面板，三端零代码零发版 -> 插入决策落账，可回滚。

模块详注

① 端层

薄客户端原则不变量
端只做两件事：渲染事件流、上送意图流。路由、压缩、审批判断等 agent 逻辑出现在任何一端都会导致多端行为分叉。CLI 从"agent 的宿主"降级为"协议的参照实现"，语义最全但无特权。加端 = 写一个客户端，内核零改动。
CLI / DESKTOP / WEB / IDE·移动演进
Desktop 的系统级能力（剪贴板、截图、全局热键、通知）经意图流上送、以事件流返回，本身不含逻辑；Web 的价值在会话共享、远程批准、复盘回放；IDE / 移动是开放性的预留位。

② 会话协议层

协议 = 账本的外化不变量
事件流里下发的每个事件就是内核记账 append 的账本条目，协议层只是把账本实时广播给挂上来的端。因此回放 = 把存储的事件流再发一遍，复盘回放与实时观看共用同一 schema。协议核心 schema 是内核不变量，插件扩展走命名空间。
openx serve新增
会话长存在 serve 进程，客户端 attach / detach。一次解决三件事：关终端 agent 继续跑（tmux 语义）、多端同看一会话、未来长存队友（team 的队友 = serve 管理的子会话）。
UI slot 事件新增
协议新增 ui_slot_registered / updated / removed 事件族：插件对界面的修改全部以此为载体。端是哑渲染器，因此 UI 插件对所有端通用，加插件永远不等于客户端发版。布局几何受保护：只加面板 / 行，输入框、主转录区、权限面板是内核领地。

③ 微内核四职责

装配照旧
v3 的 loader 五阶段、ctx 给予 / 拒绝面、注册表 IPC、逐类型验证器、失败隔离舱、inventory 只读投影，全部保留。两处变化：发现阶段的 base 列表换成动态 base 计算；激活阶段新增"会话内动态插入"路径（走同一校验，仅限热插分级允许的贡献点）。
把关收编
v2 右脊控制平面收编入内核。安全棘轮、权限裁决、远程批准照旧；资源闸把原散落在 loop 不变量（轮次、停止语义）与预算机制中的安全部分析出集中，任何 loop 槽实现每轮必过；新增晋升门--动态插入的非只读贡献须用户确认并先灰度到当前会话。
记账升格
会话 JSONL 升格为证据系统：唯一事实源、append-only、可回放、可审计、可归因。每次进化晋升、脚手架退场、插件插入与回滚，决策本身也记账--将来追问"为什么这个模块没了 / 这个插件哪来的"，答案在账本里。

④ LOOP 核心与零件层

loop 槽核心降级
接口形状（意图进、事件出、工具调用必经执行闸、每轮必过资源闸）是内核不变量，实现进槽。默认实现 = 现有 harness loop，行为≡现状；预留 model-native 位：模型自持循环，内核退为事件中继 + 闸门 + 记账。协议事件形态从第一天按后者设计，未来切换时多端 / 回放 / 审批语义零改动。装配 loop 的机制必须独立于 loop--这是"换 loop 不换产品"的前提，也是内核在 loop 之上的原因。
执行槽 / 协调槽 / 灰区双槽照旧
执行槽两阶段骨架（串行审批 -> 并行执行）的形状不变；"工具必须过闸"由把关层强制，与槽实现无关。协调槽 Mailbox / TaskBoard / Roster 接口照旧，默认会话式实现。压缩策略槽暂不开放，审计闸门槽倾向开放且只紧不松。
零件层全可换
Provider（重试 / 退避 / 超时归内核，实现可换）、Context（历史 + 组装 + 超限压缩）、Executor（闸门在内核，执行可换）、Tools（模型的手，内置 + MCP 适配器 + 用户插件聚合视图）。

⑤ 插件层（纵贯）

候选池新增
进入池中的插件一律预校验 + 签名 + 自描述贡献声明（contributes = [ui_slot(…) | tool(…) | event(x-*.*) | hook(…) | prompt(…) …]）。三个来源同池：第三方（市场）、用户（本地目录）、模型自产（进化引擎产物）--同源同门，无后门。
模型配对，内核定位新增·标准六
模型决定"用哪个插件、建议放哪个贡献点"，但贡献点由内核枚举，模型不能发明位置。位置 = 内核不变量，配对 = 模型可演进。prompt injection 最坏结果是推荐错插件，不能让插件落进内核没开过的口子。
晋升门与热插分级新增
校验（形状 / 越界 / 只紧不松）通过后，非只读贡献须用户确认，先灰度到当前会话再扩散。热插三档：UI slots / prompt 片段 / tools / 命名空间事件可会话内热插（纯加法，回滚 = 卸载）；providers / 记忆后端 / 协调实现只能会话边界换（有状态）；loop 槽 / 执行槽 / 权限闸 / 账本格式仅 boot 装配，永不热插。
UI 插件的真实形态新增
"修改前端界面"不需要碰前端：插件贡献的是协议里的一条 slot 声明 + 渲染规格，端只执行渲染。任何 UI 插件对所有端通用，加插件永远不等于客户端发版。布局几何受保护：只加面板 / 行，输入框、主转录区、权限面板是内核领地。

⑥⑦ 脚手架与演进

模型能力档案 / 动态 base新增
档案按模型版本声明能力面（context、native_summarization、native_planning、parallel_tools、self_correction…），与协议层的版本协商对称：一个面向端，一个面向模型。脚手架以 requires / exit_when 声明依赖，loader 据此计算该模型下的组合。换模型、模型升级 -> 组合自动变化，零代码改动。
脚手架退场将消融
退场三步：评测门（证据不是声明）-> 决策记账 -> 从动态 base 摘除。摘除不是删除：代码留在仓库，模型降级时经回归评测自动回挂。harness loop 默认实现是最大的脚手架，也是消融收益最大的一块--摘除后 harness 收敛到"中继 + 闸门 + 记账"终局形态。
双棘轮新增
安全棘轮单向只紧不松；能力棘轮双向跟随模型实测，以退场评测为证据门。两棘轮方向相反、性质对称，共同回答"什么永远不变、什么随时可变"。TCB 对两者都关闭：进化引擎能产出候选插件、提出退场建议，但棘轮与评测门本身不可贡献。
